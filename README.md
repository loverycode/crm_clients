# ClientFlow - Система учёта клиентов

## Назначение

Приложение предназначено для автоматизации учёта клиентов компании.
Оно позволяет менеджерам по продажам и администраторам хранить
информацию о клиентах, отслеживать их статус, назначать встречи с
клиентами и быстро находить нужные контакты, что повышает
эффективность работы с клиентской базой.

## Целевая аудитория

- Менеджеры по продажам
- Администраторы компаний
- Сотрудники отдела маркетинга

## Предметная область

Сервис относится к классу CRM-систем (Customer Relationship
Management). Основные сущности предметной области — клиент и
встреча с клиентом. Клиент может иметь несколько встреч; одна и
та же дата не может быть занята у клиента дважды активной (не
отменённой) встречей.

## Основные сущности

### `Client` — клиент

Объект `Client` представляет клиента компании.

Основные атрибуты:

- `id` — уникальный идентификатор клиента;
- `name` — имя или название клиента;
- `contact` — контактные данные (телефон, e-mail);
- `status` — статус взаимодействия («Новый», «В работе», «Завершено»);
- `created` — дата создания записи.

Основные методы:

- `update_status()` — изменить статус клиента;
- `is_valid_contact()` (`@staticmethod`) — проверить, что контакт
  указан;
- `from_data()` (`@classmethod`) — создать клиента из словаря
  данных (используется при загрузке из JSON);
- `__str__()` — строковое представление клиента.

### `Meeting` — встреча

Объект `Meeting` представляет встречу с клиентом (аналог
бронирования).

Основные атрибуты:

- `id` — идентификатор встречи;
- `client` — объект `Client`, с которым назначена встреча;
- `meeting_date` — дата встречи;
- `topic` — тема встречи;
- `is_cancelled` — признак отмены встречи.

Основные методы:

- `cancel()` — отменить встречу (объект не удаляется из
  коллекции, изменяется только его состояние);
- `__str__()` — строковое представление встречи с учётом статуса.

## Взаимодействие объектов

Объект `Meeting` хранит прямую ссылку на объект `Client`, а не
только его идентификатор — это позволяет обращаться к данным
клиента напрямую: `meeting.client.name`, `meeting.client.contact`.

```
Meeting
├── client → Client
├── meeting_date
├── topic
└── is_cancelled
```

Активная встреча блокирует клиента на выбранную дату; отменённая
встреча — не блокирует, и на эту дату можно назначить новую
встречу.

## Возможности

- добавление нового клиента с проверкой корректности данных;
- просмотр списка всех клиентов;
- поиск клиента по имени или контактным данным;
- изменение статуса клиента;
- фильтрация клиентов по статусу;
- сортировка клиентов по имени, статусу или дате создания;
- проверка доступности клиента на выбранную дату;
- назначение встречи с клиентом (с запретом двойной записи на
  одну дату);
- отмена встречи (без удаления из истории);
- просмотр списка встреч с указанием их статуса;
- сохранение и загрузка данных клиентов и встреч из JSON-файлов.

## Формат хранения данных

В JSON-файлах хранятся только данные и идентификаторы связанных
объектов — сами объекты не дублируются.

Клиенты (`data/clients.json`):

```json
[
  {
    "id": 1,
    "name": "Иван Петров",
    "contact": "+7-999-123-45-67",
    "status": "В работе",
    "created": "2026-09-15"
  }
]
```

Встречи (`data/meetings.json`) — вместо объекта клиента хранится
`client_id`:

```json
[
  {
    "id": 1,
    "client_id": 1,
    "meeting_date": "2026-09-20",
    "topic": "Обсуждение условий договора",
    "is_cancelled": false
  }
]
```

При загрузке встреч по `client_id` ищется соответствующий объект
`Client`; если клиент не найден, встреча пропускается. При
сохранении объектная ссылка `meeting.client` преобразуется
обратно в `client_id`.

## Требования

- Python 3.10+;
- pytest;
- flake8.

Установка зависимостей разработки:

```
pip install -r requirements.txt
```

Сторонних зависимостей у самого приложения нет — используется
только стандартная библиотека Python.

## Запуск программы

```
python main.py
```

## Запуск тестов

```
pytest -v
```

Тесты проверяют не только результат работы функций, но и
состояние объектов: создание `Client`/`Meeting`, их атрибуты,
строковое представление, поведение метода `cancel()` (встреча
остаётся в коллекции, но перестаёт блокировать дату).

## Проверка качества кода

```
flake8
```

## План развития

На следующих этапах планируется:

- реализовать хранение данных в базе данных (PostgreSQL/SQLite);
- создать веб-интерфейс на Django для удобного управления;
- внедрить систему аутентификации пользователей (менеджеров);
- разработать REST API для интеграции с другими системами;
- контейнеризация приложения с использованием Docker;
- настройка CI/CD (непрерывной интеграции и доставки).
