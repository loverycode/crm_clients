# CRM — клиенты, менеджеры, контакты, сделки

Консольное и веб-приложение для учёта клиентов компании, ведущих их
менеджеров, контактных лиц клиентов и сделок между клиентами и
компанией.

## Целевая аудитория

- Менеджеры по продажам
- Администраторы компаний
- Руководители отдела продаж

## Основные сущности

### `Client` — клиент

Компания или частное лицо, с которым ведётся работа.

Атрибуты: `id`, `name`, `status`, `created`.
Методы: `update_status()`, `from_data()` (`@classmethod`), `__str__()`.

### `Manager` — менеджер

Сотрудник компании, ведущий сделки с клиентами.

Атрибуты: `id`, `name`, `email`.
Методы: `is_valid_email()` (`@staticmethod`), `from_data()`
(`@classmethod`), `__str__()`.

### `Contact` — контакт

Контактное лицо у клиента. Хранит прямую ссылку на объект `Client`.

Атрибуты: `id`, `client`, `name`, `phone`, `position`.
Методы: `__str__()`.

### `Deal` — сделка

Сделка между клиентом и менеджером. Хранит ссылки на `Client`,
`Manager` и, при наличии, на `Contact`.

Атрибуты: `id`, `client`, `manager`, `contact`, `amount`, `title`,
`stage` (`"Открыта"`, `"Выиграна"`, `"Проиграна"`, `"Отменена"`).
Методы: `is_open()`, `close(outcome)`, `__str__()`.

Классы вынесены в пакет `models/`, чтобы их имена не конфликтовали
с именами Django-приложений (`clients`, `deals`).

## Веб-интерфейс (Django)

Проект состоит из трёх Django-приложений поверх объектной модели:

| Приложение | Маршруты                      | Назначение                                                                                           |
| ---------- | ----------------------------- | ---------------------------------------------------------------------------------------------------- |
| `homepage` | `/`                           | Главная страница, общий каркас `page()` и навигация                                                  |
| `clients`  | `/clients/`, `/clients/<id>/` | Список клиентов, карточка клиента с его контактами                                                   |
| `deals`    | `/deals/`, `/deals/<id>/`     | Список сделок, карточка сделки с клиентом, менеджером, контактом и признаком загруженности менеджера |

Данные читаются напрямую из тех же JSON-файлов и тех же функций
`load_*`/`find_*_by_id`, что используются в консольной версии —
отдельной базы данных и моделей Django ORM на этом этапе нет.

Страницы оформлены Bootstrap (подключается через CDN). Запрос
несуществующего клиента или сделки (`/clients/999/`,
`/deals/999/`) возвращает корректную страницу `404`, а не падает.

### Запуск веб-сервера

```
python manage.py runserver
```

Открыть в браузере: `http://127.0.0.1:8000/`

## Возможности (консольная версия)

**Клиенты:** добавление, поиск по названию, изменение статуса,
фильтрация по статусу, сортировка по имени/статусу/дате.

**Менеджеры:** добавление (с проверкой email), поиск по имени
или email.

**Контакты:** добавление контакта клиента, поиск, просмотр всех
контактов конкретного клиента.

**Сделки:** создание (с проверкой загрузки менеджера), закрытие
с указанием исхода, фильтрация по стадии, сортировка по сумме.

## Формат хранения данных

В JSON хранятся только идентификаторы связанных объектов, не
сами объекты.

```json
// clients.json
{"id": 1, "name": "ООО Ромашка", "status": "В работе", "created": "2026-09-15"}

// managers.json
{"id": 1, "name": "Анна Смирнова", "email": "anna@company.ru"}

// contacts.json — ссылка на клиента через client_id
{"id": 1, "client_id": 1, "name": "Сергей Волков", "phone": "+7-999-0", "position": "Закупщик"}

// deals.json — ссылки через client_id/manager_id/contact_id
{"id": 1, "client_id": 1, "manager_id": 1, "contact_id": 1,
 "amount": 150000, "title": "Поставка оборудования", "stage": "Открыта"}
```

## Требования

- Python 3.10+
- Django — веб-интерфейс
- pytest — тестирование
- flake8 — проверка стиля (PEP 8)
- mypy — статическая проверка типов
- autopep8 — автоматическое форматирование кода

Установка:

```
pip install -r requirements.txt
```
